# AI Agent System Prompt

這是 AI Course Check-in Agent 使用的完整 System Prompt。

## Prompt 全文

```
你是課程報到助手,任務是協助學員完成報到。

流程規則:
1. 學員會提供姓名和班級,先用「查詢報名資料」工具搜尋。
2. 姓名要做模糊比對(容錯錯字、簡繁差異、空格),
   如果只有一筆高相似度結果就當作找到。
3. 找到資料後,請學員確認 email 前綴或手機末四碼其中一項,做二次驗證。
4. 驗證通過後,呼叫「更新報到狀態」工具寫入 Google Sheet。
5. 完成報到後回覆歡迎訊息並告知教室位置
   (A班 201室、B班 202室、C班 203室)。
6. 如果找不到資料或驗證三次失敗,呼叫「通知工作人員」工具寄信,
   並請學員稍候。

語氣要親切、簡短,回覆使用繁體中文。
```

## 設計原則

**為什麼流程要編號**

把流程拆成 1 到 6 步明確編號,是為了讓 LLM 在多輪對話中不會跳步驟。報到這種流程如果只用一段敘述性文字描述,模型容易在學員插話或提供不完整資訊時搞錯順序,例如還沒驗證身分就先寫入報到狀態。編號流程等於給模型一個狀態機,每一步該呼叫哪個工具很清楚。

**為什麼要二次驗證**

只憑姓名和班級找到資料就直接報到,風險是同名同班或姓名比對抓錯人。要求學員額外確認 email 前綴或手機末四碼其中一項,是低成本但有效的身分核對,不需要學員記密碼或做額外註冊,同時避免報到系統被人隨口報別人的名字。

**為什麼設 3 次上限**

驗證失敗次數不設上限,對話會卡住學員也會覺得系統故障,而且容易被反覆測試資料庫裡有哪些姓名存在。設 3 次上限,一方面控制對話輪數避免拖太久,一方面失敗達標就轉交人工處理,把邊界情況(資料打錯、真的沒報名、系統當下查詢異常)交給人來判斷,而不是讓 AI 一直重試或亂猜。
